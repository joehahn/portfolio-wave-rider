The watchlist-curator agent was called biweekly over the 2026-07-22 to 2026-08-18 window. At each rebalance it read a date-clean news pool for the preceding biweekly window. Each pool is the live WebSearch forward corpus for the preceding window — no backtest news is used; see the RBS for the news-side view. The curator proposed adds and removes against the active watchlist; the optimizer then ran mean-variance on the revised watchlist. Each rebalance is marked by an orange square on the curator curve in chart 2; hover over one to see that rebalance's adds, removes, and the curator's rationale. 9. P&L per article vs news source

Plot 8's total $ P&L per source divided by how many articles that source contributed to the pools (its footprint, shown as N art.). Signal density: high = a source that produced gains from few articles; near-zero/negative with many articles = low-signal, a block-list candidate. Two bars are not per-article rates: seed (CBT inheritance) (the day-0 weights this run started from) and inherited (CBT watchlist) (tickers the optimizer funded that this run never added, arriving on the starter watchlist). Neither has a pool-article footprint, so they show TOTAL $ P&L and are labelled as such — without them the chart would show only the curator's own adds, which can read as all-losses while the portfolio is up.
