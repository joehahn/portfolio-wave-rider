Parameter sweep — zero-cost optimizer knobs

150 configs = concentration_cap × risk_aversion (λ) × optimizer_lookback, replayed on the fixed 2-year curation set (gkg-2yr-weekly). These knobs touch only the mean-variance replay, not the curator, so the whole grid costs $0 (no LLM). Ranked by Information Ratio (annualized active return ÷ tracking error vs SPY — consistency of beating the benchmark). SPY returned +85% over the window. ★ = best in column.

All in-sample. These rank candidate configs to forward-test; they don't prove an optimum. Read the IR t-stat (|t|>2 ≈ real vs luck), the bootstrap CI (error bar on annualized return), and H1/H2 stable (does the edge hold in both halves) before trusting any row.

Column meanings:
cap / λ / lookback — the config: concentration cap (max weight per position) · risk-aversion λ · optimizer lookback (days of prices used to estimate μ/Σ).

t-stat — statistical significance of the IR (= IR·√years). |t|>2 ≈ the edge is real rather than luck.
Sharpe — (annualized return − 4% risk-free) ÷ total volatility. Standalone risk-adjusted return (per unit of total risk).
Calmar — annualized return ÷ |max drawdown|. Return earned per unit of worst peak-to-trough loss.
alpha — annualized return − SPY's annualized return (excess over the benchmark).
ann — annualized return · maxDD — deepest peak-to-trough drawdown · total — total return over the whole window.
hit-rate — share of rolling 6-month windows in which the config beat SPY.
ann CI [5,95] — block-bootstrap 5–95% confidence interval on the annualized return (the error bar).
H1/H2 stable — whether IR > 0 in both halves of the window (a yes means the edge isn't a one-half artifact).

3. LLM comparison — curator model (same pools + profile config)

Every model reads the same news pools and replays at the profile config (cap 0.8 / λ 2.0 / 30d); the only variable is the curator LLM. The decision columns are the ones that matter: agree = share of weeks the model made the identical add/remove call as the reference (top row), valid-JSON = share of calls that parsed, $/run = curator LLM cost of a full 157-week curate, and curator time = wall-clock of those 157 calls (≈ per-call latency × 157; excludes GKG ingest + optimizer replay).
